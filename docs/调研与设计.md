# GitHub 同类项目调研与设计取舍

本项目在编码前调研了以下开源实现。调研用于理解成熟功能与边界，项目未复制这些仓库的源码。

## DOCX DIFF

仓库：https://github.com/jomardyan/DOCX-DIFF

可借鉴点：

- 将段落、表格单元格、页眉和页脚抽象成有位置的结构化块
- 先对齐文档块，再在替换块内做词级差异
- 拖放、后台处理、统计信息、键盘快捷键
- 原子写入、拒绝覆盖源文件、对大文档提供降级策略

本项目优化：

- 输出不是 HTML/TXT，而是保留新版本结构和版式的 DOCX
- 中文按单字、英文数字按词组进行细粒度标注
- 直接处理 OOXML，覆盖脚注、尾注和文本框文字

## Open XML PowerTools WmlComparer

仓库：https://github.com/OfficeDev/Open-Xml-PowerTools

可借鉴点：

- 比较需要覆盖嵌套表格和文本框
- Word 文档应按多个 story part 分别处理
- 复杂 DOCX 比较必须保留包结构与关系

本项目取舍：

- PowerTools 以 Word 修订标记为目标，本项目按需求改用可选颜色高亮
- PowerTools 已归档且依赖 Open XML SDK；本项目不引入外部运行依赖
- 本项目明确忽略格式变化，只比较纯文字

## Python Redlines 和 Docxodus

仓库：https://github.com/JSv4/Python-Redlines

可借鉴点：

- 使用结构感知模型降低表格错配
- 将移动、插入、删除、替换分开统计
- 全程离线、自托管、不依赖 Microsoft Word

本项目取舍：

- 不引入 Python 和现代 .NET 二进制运行时，减少部署体积与供应链依赖
- 第一版不写入修订标记，也不比较表格属性和格式属性

## ExtDiff

仓库：https://github.com/ForNeVeR/ExtDiff

可借鉴点：

- 旧版本和新版本双槽位拖放流程直观
- 适合作为桌面工具的一步式工作流

本项目优化：

- 不使用 Word COM 自动化，因此不要求安装 Office
- 不启动外部 Word 进程，对比引擎完全内置

## 最终设计

- 原生 WPF 单窗口桌面程序
- 两个明确标注的文件槽位，支持选择与拖放
- 单一主要操作按钮，避免复杂设置
- 标准 Word 高亮色下拉选择
- 输出路径可见且不可覆盖源文件
- 背景线程处理并显示百分比进度
- 正文、表格、页眉页脚、脚注尾注、文本框均纳入比较
- 段落级结构对齐后进行词级差异，新版本中新增或替换的文字使用用户选择的高亮色
- 旧版本中被删除或替换掉的文字以红色删除线重新插入，整段删除按原顺序插入对应位置附近
